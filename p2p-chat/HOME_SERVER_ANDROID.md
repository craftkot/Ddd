# EHTID Chat v0.8 — домашний сервер Windows

Android 7+; `com.ehtid.p2pchat`. Рабочая ветка `feature/p2p-chat`.

В этой версии EHTID Home Relay (архив
`EHTID-Home-Relay-Windows-v1.zip`) — основной транспорт чата.
Запросы отправляются на **введённый пользователем HTTPS-адрес**.
В публичный `ntfy.sh` приложение больше не подключается автоматически.

## Как подключить

1. На ПК с Windows развернуть `EHTID-Home-Relay-Windows-v1.zip` в постоянную папку.
2. Запустить `START-STABLE-TAILSCALE.cmd` для стабильного адреса
   `https://<компьютер>.<tailnet>.ts.net` (понадобится установка Tailscale и включение Funnel).
   Альтернатива — `START-EHTID.cmd` с временным Cloudflare Quick Tunnel.
3. Убедиться на ПК, что `http://127.0.0.1:8765/health` выдаёт JSON с `"ok":true`.
4. Установить EHTID Chat v0.8 **поверх v0.5–v0.7 без удаления**.
5. Нажать **«Подключить домашний сервер»**, вставить публичный HTTPS-URL без пути,
   выбрать «Проверить сервер», затем «Сохранить и подключить».
6. На втором телефоне указать тот же сервер и код комнаты. Участникам не
   нужно обмениваться SDP/P2P-приглашениями.
7. В журнале чата «Принято реле» означает, что сервер подтвердил получение,
   но не означает доставку или прочтение другим телефоном.

## Поведение при выключении ПК

Телефон повторно подключается после запуска ПК. Неотправленные сообщения
сохраняются локально в очереди (до 100), а сервер хранит до 250 последних
зашифрованных событий в комнате на срок до 7 суток. Локальная история
сохраняется в Android. Cloudflare Quick Tunnel при новом запуске может сменить
URL; Tailscale Funnel использует стабильное имя при неизменной конфигурации.

## Проверка

Android использует следующий протокол, поддерживаемый Windows-сервером:
- `GET /health`: проверка работоспособности и имени сервера;
- `POST /ehtidp2p-{40 hex}`: шифрованный пакет (v1 или frag1);
- `GET /ehtidp2p-{40 hex}/json?since=30m|e[16digits]`: события JSON Lines.

Один код комнаты определяет и топик, и ключ AES-GCM. HTTPS защищает канал
до туннеля; Cloudflare или Tailscale является внешним транспортом.
Для реальной защищённой эксплуатации требуется отдельный аудит протокола.

Отдельная ручная P2P-сеть WebRTC доступна как опция в настройках, но **по
умолчанию выключена**. Публичный ntfy.sh специально не используется как
неявный резервный сервер.

## Ограничения

В выходные без ПК обмен сообщениями не работает, хотя исходящие сообщения
сохраняются на телефоне. Для доставки с другого телефона требуется
включённый ПК, запущенный Relay EXE и работающий туннель. Обновление
настройки сервера не требует переустановки Android-приложения.
